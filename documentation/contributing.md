# 贡献指南

## 1. 项目概述

Rusty-TypeScript 是一个用 Rust 实现的 TypeScript 运行时项目，目标是超越 V8，提供高性能、低内存使用的 TypeScript 执行环境。

## 2. 开发环境设置

### 2.1 系统要求

- Rust 1.70+ (stable)
- Node.js 16+ (用于前端开发)
- pnpm (用于前端包管理)
- Git

### 2.2 克隆仓库

```bash
git clone https://github.com/rusty-typescript/rusty-typescript.git
cd rusty-typescript
```

### 2.3 安装依赖

```bash
# 安装 Rust 依赖
cargo build

# 安装前端依赖
cd frontends/homepage
pnpm install
```

## 3. 开发流程

### 3.1 分支管理

- `main`: 主分支，包含稳定版本
- `develop`: 开发分支，包含最新的开发代码
- 特性分支: 用于开发新功能，格式为 `feature/feature-name`
- 修复分支: 用于修复 bug，格式为 `fix/bug-name`

### 3.2 开发步骤

1. **创建分支**: 从 `develop` 分支创建新的特性或修复分支
2. **开发代码**: 实现功能或修复 bug
3. **运行测试**: 确保代码通过所有测试
4. **提交代码**: 提交代码并编写清晰的提交信息
5. **创建 PR**: 向 `develop` 分支创建拉取请求
6. **代码审查**: 等待代码审查和反馈
7. **合并代码**: 代码审查通过后，合并到 `develop` 分支

### 3.3 提交规范

提交信息应遵循以下格式：

```
<类型>(<范围>): <描述>

<详细描述>

<可选的脚注>
```

**类型**：
- `feat`: 新功能
- `fix`: 修复 bug
- `docs`: 文档更新
- `style`: 代码风格修改
- `refactor`: 代码重构
- `test`: 测试更新
- `chore`: 构建或依赖更新

**范围**：
- `compiler`: 核心编译器
- `ir`: 中间表示
- `jit`: JIT 编译
- `type-checker`: 类型检查
- `runtime`: 运行时环境
- `ffi`: FFI/NAPI
- `frontend`: 前端功能
- `build`: 构建系统

**示例**：

```
feat(compiler): 实现 TypeScript 词法分析器

添加了完整的 TypeScript 词法分析器，支持所有 TypeScript 关键字和语法结构。

Closes #123
```

## 4. 代码规范

### 4.1 Rust 代码规范

- 遵循 [Rust 代码风格指南](https://github.com/rust-lang/rustfmt)
- 使用 `rustfmt` 格式化代码
- 使用 `clippy` 进行代码 linting
- 所有公共结构体、枚举、方法、字段都需要文档注释
- 禁止使用后置注释

### 4.2 前端代码规范

- 遵循 [Vue.js 风格指南](https://vuejs.org/style-guide/)
- 使用 ESLint 进行代码 linting
- 使用 Prettier 格式化代码
- 所有公共组件和方法都需要文档注释
- 禁止使用后置注释

### 4.3 文档规范

- 使用 Markdown 格式
- 保持文档清晰、简洁、准确
- 文档应与代码保持同步
- 提供必要的示例和说明

## 5. 测试要求

### 5.1 测试类型

- **单元测试**: 测试单个组件或函数
- **集成测试**: 测试多个组件的交互
- **性能测试**: 测试性能和内存使用
- **类型系统测试**: 测试类型检查功能

### 5.2 测试覆盖率

- 代码覆盖率应达到 80% 以上
- 重点测试核心功能和边界情况
- 定期运行测试套件

### 5.3 测试运行

```bash
# 运行 Rust 测试
cargo test

# 运行前端测试
cd frontends/homepage
pnpm test

# 运行性能测试
cargo bench
```

## 6. 代码审查

### 6.1 审查要点

- 代码质量和可读性
- 功能正确性
- 性能和内存使用
- 安全性
- 代码风格和规范
- 测试覆盖

### 6.2 审查流程

1. 提交拉取请求
2. 自动运行测试和 linting
3. 团队成员进行代码审查
4. 解决审查意见
5. 测试通过后合并

## 7. 发布流程

### 7.1 版本规划

- **v0.1.0**: 核心功能实现

### 7.2 发布标准

- 所有测试通过

- 文档完善
- 性能达到 V8 的 80%
- 内存使用低于 V8 的 70%

## 8. 常见问题与解决方案

### 8.1 构建问题

**问题**：构建失败
**解决方案**：
- 检查 Rust 版本
- 确保依赖已安装
- 运行 `cargo clean` 后重新构建

### 8.2 测试问题

**问题**：测试失败
**解决方案**：
- 检查测试代码
- 运行单个测试进行调试
- 查看测试输出和错误信息

### 8.3 性能问题

**问题**：性能不符合要求
**解决方案**：
- 使用性能分析工具
- 优化算法和数据结构
- 减少内存分配
- 实现缓存机制

### 8.4 类型系统问题

**问题**：类型检查失败
**解决方案**：
- 检查类型定义
- 确保类型兼容性
- 修复类型错误
